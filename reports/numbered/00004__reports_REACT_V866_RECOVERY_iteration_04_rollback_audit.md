## Подтверждённые причины

### 1. Header: чрезмерная область действия

`react-header-transparent.css` использовал селектор
`.efhc-game-header *` и оба псевдоэлемента всех потомков.
Принудительно обнулялись background, border-color, box-shadow, text-shadow,
filter/backdrop-filter; для псевдоэлементов задавался content:none.
Это затронуло аватар, внутреннее оформление его значка, профиль, баланс,
статусы и кнопки. Удаление подложки было реализовано как стирание материалов
всего дерева. Конкретный получившийся вид не был согласован с OWNER.
Ответственность за неверную трактовку и слишком широкую реализацию — разработчика.

Изолированное отключение только отвергнутых CSS в браузере при 390px/CT-01
возвращает девять оформленных поверхностей Header вместо нуля.
На снимках видно исчезновение и возврат обрамления аватара, профиля, баланса
и четырёх кнопок. Геометрическая сохранность не защитила визуальную идентичность.

### 2. Прогресс-бары: унификация уничтожила исходные различия

Генератор `chroma()` заменял почти все насыщенные цвета на
`--efhc-ct-accent` и его светлые/тёмные смеси; нейтрализовал часть подложек.
Дополнительно для PB-01/PB-24…PB-35 задавался один общий градиент и glow.
Тем самым исходные цвета отдельных моделей переставали участвовать в рендере.

Конкретное измерение при CT-01:
- без отвергнутого CSS PB-24 имеет градиент rgb(124,92,255) → rgb(167,139,250);
- PB-25 имеет rgb(24,119,166) → rgb(34,158,217);
- с отвергнутым CSS оба получают один и тот же CT-01 градиент.

Равная геометрия и сходство после собственного перекрашивания были ошибочно
использованы для удаления вариантов из переключателя. Это не доказательство,
что исходные цветовые реализации являются полными визуальными дублями.
Уточнение о цвете темы было реализовано чрезмерно широко, без сохранения
индивидуальности моделей и без визуально согласованного образца.

### 3. Каскад и геометрия заменены принудительным нормализатором

Progress-адаптер делал `all:revert!important` для двух элементов и их
псевдоэлементов, затем повторно задавал объявления как `!important` внутри слоя.
При извлечении селекторы обрезались начиная с класса progress track/fill,
что отбрасывало часть исходного контекста предков. Отдельные theme-контексты
вообще исключались. Это уже преобразование авторской системы правил,
а не точный перенос каскада HTML.

Общие min/max-height, clamp высоты заполнения и принудительное центрирование
заменяли часть собственных решений моделей. В изолированной пробе PB-03/PB-04/
PB-11/PB-12 получали одну высоту рейки 10,0312px и заполнения 8,01562px.
Сам по себе диапазон ±15% не доказывает сохранение формы и композиции.
Адресное восстановление исходного правила было заменено новой системой
переопределений.

### 4. Проверки подтверждали собственную реализацию

Тест Header требовал отсутствия поверхностей, теней и рамок у всех потомков;
поэтому разрушение принятого оформления считалось PASS.
Progress-тест проверял оттенок активной CT, заданные диапазоны размеров,
несколько CSS-признаков и число различных строк-сигнатур.
Он не сравнивал пиксели с HTML или принятым Header.
Большая матрица напрямую меняла data-атрибуты и ставила прогресс 55%;
она не доказывала все пользовательские состояния, края 0/100% и полную
сохранность настроек через реальные действия.

Сохранение скриншота само по себе не является визуальным сравнением.
1980/390/180 успешных сочетаний не дают основания объявлять внешний вид
восстановленным. Обязательная визуальная проверка не была превращена
в независимый критерий допуска. OWNER обнаружил регрессию после публикации.
Защитный статус Header был неправильно ослаблен трактовкой задачи.

## Обязательные ограничения после аудита

Header возвращается под прежнюю защиту. Без конкретного согласованного
образца его материалы и дочерние декоративные элементы не изменять.
Новые правки прогресс-баров выполнять отдельно, начиная с одного физического
варианта, исходного контекста HTML и сравнения до/после на одинаковом состоянии.
Не нормализовать весь каталог и не удалять варианты по ограниченной сигнатуре.
Для дальнейших изменений необходимы независимые визуальные эталоны/снимки,
сохранение отличительных материалов и проверка реальных переключений,
перезагрузки, крайних значений и ширин. Эти работы сейчас не выполнялись.

Откат возвращает прежние ограничения и известные дубли базовой реализации;
он не объявляется новым исправлением всех прогресс-баров.
Визуальная проверка возврата остаётся за OWNER.
