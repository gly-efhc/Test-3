## Текущий этап

Восстанавливается общая USER-оболочка: шапка, навигация, десять цветовых тем,
преобразование выбранного шаблона в CSS-стиль и адаптивная ширина. Эталонные
цвета и геометрия берутся из HTML, интерфейс остаётся React с действующими
обработчиками и состоянием. Замороженные CSS v866 сохраняются побайтово.

Это промежуточная версия для визуальной приёмки. Полная визуальная приёмка
остальных экранов/вариантов, функций, адаптивных состояний и отдельного Browser Shop
ещё не выполнена. Равенство каталогов не является доказательством равенства
отрисовки всех 236 вариантов. Прежние диагностические ошибки Pages остаются
видимыми и не объявляются исправленными этим этапом.

## Контроль синхронизации

- `frontend/tests/parity/v866-contract.json`: извлечённые из HTML каталоги,
  значения по умолчанию, соответствия CSS, состав шапки и десять палитр.
- `ci/parity/extract_v866.py`: повторное извлечение/проверка из архива с
  проверкой его SHA и SHA самого HTML. Результат нельзя обновлять по React.
- `ci/parity/generate_shell.mjs`: воспроизводимый USER-адаптер шапки и навигации
  из неизменного CSS v866. Исходные селекторы, порядок и объявления сохраняются;
  дополнительная область действия ограничивает адаптер USER-оболочкой.
- `frontend/tests/parity/contracts.test.mjs`: реальные функции нормализации,
  циклического выбора, отображения стилей, палитры и контрольные суммы CSS.
- `frontend/tests/parity/browser.mjs`: отрисованная оболочка, все шесть шапок,
  десять тем через переключатель, сохранение/перезагрузка, D8, ширины и маршруты.
  Внешние запросы заблокированы в тестовом браузере; реальные операции не выполняются.
- `efhc-parity.yml`: проверки рабочей ветки/PR.
- `efhc-pages.yml`: публикация изменений `site/` из main, только после успешных
  новых проверок. Checkout привязан к SHA запуска. Историческая расширенная
  диагностика сохраняется отдельно и не заменяет эти блокирующие проверки.

Для установки/сборки используется существующий `package-lock.json`. Browser
проверки используют отдельный `playwright-core@1.64.1`, а не production dependency.

Команды из `site/frontend` после установки зависимостей:

```sh
npm run test:html-react-parity
npm run test:frontend-regression
```

Проверка происхождения адаптера из корня репозитория:

```sh
node site/ci/parity/generate_shell.mjs --check
python3 site/ci/parity/extract_v866.py --archive /path/FRONTEND_v866.zip \
  --contract site/frontend/tests/parity/v866-contract.json --check
```

Рабочая ветка: `recovery/html-v866-parity`. OWNER разрешил перенос результатов
в main и промежуточные публикации на https://gly-efhc.github.io/Test-3/ для приёмки.

Дополнительные обязательные проверки: `interactions.mjs` воспроизводит реальные
выходы, вложенные жесты, геометрию и Back/Exit; `templates.mjs` проходит цикл
доступных вариантов в 17 семействах; `routes.mjs` проверяет все статические
маршруты, ссылки и цепочку навигации внутри одной сессии. Каталоги AD/BS не
объявляются восстановленными: `/ads` — действующий alias `/tasks`, Browser Shop
имеет самостоятельный renderer. Часть вариантов AM и отдельных USER-семейств
может пока иметь одинаковое оформление; смена сохранённого selection и полное
визуальное соответствие — разные критерии. Физическая проверка на Android
остаётся отдельной от браузерной имитации host callbacks.
